# Sources used in the research that Rabbit was missing

**16 November 2026 — 25 proposals submitted, all awaiting human review.**

I found **17 source collections missing from Rabbit**, **five additional access routes for existing sources**, and **three useful usage or limitation notes**. All 25 are now in Rabbit’s review inbox with a link to the relevant GitHub evidence at a fixed revision. None has been approved or enabled by this audit. The published catalog remains **1,556 sources and 2,517 access methods**.

Seven of the 17 proposed new sources were actually used in an investigation. The other ten were inspected or tested during source research and scoping. That distinction is recorded explicitly. A source mentioned in a planning document is not automatically a source we successfully used.

The clearest omissions are FinePDFs from the Afghan-document work; Washington Metro ridership data from the activity test; the two Canadian earthquake catalogues and Petrinex from the Alberta investigation; and the historical laser-survey archives already reviewed in October. Some familiar defence sources were already in Rabbit’s candidate list and were not submitted again.

The useful result is a record of experience: what we tried, what we obtained, what it helped us do and where it failed. A longer list of links alone would lose the most valuable part of this work.

## What the automatic check said

Rabbit’s first check marked **22 proposals for consideration** and **three for more evidence**: the Alberta earthquake catalogue, Grants.gov’s daily extract, and Security Force Monitor’s training data. It did not fetch or assess the underlying data.

My assessment is that all three are supportable **as dated, limited catalog entries or routes**. Their caveats must stay visible:

- The Alberta catalogue was downloaded in the October experiment. Missing magnitudes limit a particular test; they do not make the catalogue nonexistent.
- The Grants.gov extract was parsed in October. Its [current official page](https://www.grants.gov/xml-extract) lists a 16 November download. Opportunities describe funding intent, not awards, and this audit did not redownload the file.
- Security Force Monitor’s [publisher page](https://trainingdata.securityforcemonitor.org/) and the historical sample support an entry. Missing dates and rows marked unverified are data-quality limits. The full database was not downloaded in this audit.

These are recommendations for the curator, not approvals. I retained the automatic flags and the original caveats. Changing honest wording just to obtain a better automated recommendation would make the catalog worse.

## Implication for keeping track of investigative work

Rabbit can preserve these links and notes now, but it does not yet have a dedicated project-by-source usage history. A useful future view would show the investigation, date used, exact data version, access route, outcome and evidence link beneath each source. The accompanying machine-readable audit already separates these fields so a later interface can use them.

“Used successfully” should mean the stated records were obtained and inspected. It should not imply that the investigation produced a story, that the source is complete, or that its access route still works today.

### Current checks and their limits

This audit reopened selected publisher documentation and landing pages on 16 November. It did not redownload large files. The direct defence-contract page and LINZ documentation returned 403 to the web retrieval tool; no bypass was attempted. Vancouver and NIH pages exposed limited dynamic content. The US Base Project landing page did not establish current workbook availability. These limitations are preserved alongside the older acquisition evidence.

The military-boundary service currently describes worldwide sites, while the October query returned only `usa` for the sampled country field. Both observations are preserved; current feature coverage needs its own query before making a global-coverage claim.

The [current UK Intellectual Property Office guide](https://www.gov.uk/government/publications/one-ipo-patents-service-details/one-ipo-patents-service-details) still describes the register interface as under development. A proposed service must not be recorded as a working bulk feed.

### Maintenance lesson

The repository contains useful records that never reached the site because source work, catalog additions and source-use notes were kept separately. Keep one explicit source-to-project record when an acquisition or meaningful test finishes. Record failures as well as successes, and send genuinely new collections or access routes into the human-review inbox. Do not manufacture a new source for every experiment, file or publisher URL.
